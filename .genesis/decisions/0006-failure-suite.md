# ADR 0006 — The failure suite: what each case pins, what it deliberately does not, and the findings against prior claims (three self-found, two verifier-found post-approval)

- **Date:** 2026-09-22
- **Status:** accepted
- **Phase / milestone:** M7 (VERIFY) — `tests/failures/`

## Context

`memory-plan.md` §10 names one required, specific failure: a same-tick race between a superseding memory arriving and a query being answered. `PLAN.md`'s M7 row restates it as two proofs (an interleaved-affirm test, a clock-inconsistent-tie test) plus the required shared-deliverable deliberate-failure test (the fair-baseline-vs-tombstone contrast, run as a real, passing test). This milestone's own brief additionally asks for several already-learned behaviours to be pinned as regression guards, and poses two open questions about what else is worth pinning. `lib/**` and `domains/**` are frozen — this ADR records ten test files under `tests/failures/**` only, plus the reasoning for one case that was drafted, found redundant against a concurrently-merged `main`, and deleted rather than kept for its own sake.

## Decision 1 — the standard this suite is held to, and how it was checked

`~/Desktop/shadow-run/tests/failures/` was read in full before writing anything here (`case-1-toctou.test.ts` and `case-5-gate-never-consulted.test.ts` closely, the other three for pattern). Three disciplines were carried over directly: every file states, in its own header, what it pins and why the failure matters; every file carries an explicit FULL PIN or HONEST PARTIAL PIN label, and the label is checked against what the file's own assertions actually prove, not what its prose claims; and a design-doc or ADR claim found wrong while building a case is corrected in that case's own header, not silently worked around. Two of this suite's ten cases (10 and 6) found exactly this kind of thing while being built — see Decision 3.

## Decision 2 — the two required §10 races, and why one is a full pin and the other is not

**Case 1 (`case-1-interleaved-affirm-during-query.test.ts`) — HONEST PARTIAL PIN.** This codebase has no concurrency primitive anywhere in `lib/store/**`/`domains/personal-assistant/**` — no `await`, no callback, no generator inside `queryBelief`/`recordFact`/`query`. A true interleaving, where a second call executes while a first is paused mid-body, cannot be constructed, because there is no pause point to interleave at; JavaScript's run-to-completion semantics make it structurally impossible in this single-threaded runtime. What IS real and constructible: a caller can capture a `StoreState`/candidates snapshot, let a contending `recordFact` commit, and only then finish its own query computation against the stale snapshot — reproducing the exact CONSEQUENCE a true interleaving would have caused, by fixed ordering rather than concurrency. Case 1a builds exactly that and gets a real, reproducible stale `"believed"` answer — the vulnerability is not hypothetical. Case 1b then runs the identical two operations through the discipline every real caller in this codebase already follows (`scripts/demo-memory.ts`, `store.test.ts`: thread `state` monotonically, never hold a captured-earlier reference) and shows the race does not manifest there. Both halves are real, run, and reported; the label is partial because (a) is a simulation by fixed ordering, not concurrency, and because nothing under `lib/store/**`/`domains/**` gives a TYPE-LEVEL guarantee against a future caller (M8's UI, most plausibly) reintroducing 1a's exact shape — the discipline that prevents it today is convention, not enforcement, and this file says so rather than overclaiming a guarantee the type system does not actually provide.

**Case 2 (`case-2-clock-inconsistent-race.test.ts`) — FULL PIN.** Unlike Case 1, this is a genuine, order-independent, mechanical property of `contradict()` (frozen): two memories sharing an identical `believedAt` fail closed to `not-comparable`/`"clock-order-violated"` regardless of which one a caller passes as "older" versus "newer" — proven by literally reversing the argument order and the array order and getting the identical `disputed` outcome both times (Case 2c's two sub-tests). This required no simulation of anything unconstructable; it is a real property of code that already exists, checked from both directions. A genuine, non-tied ordering (Case 2d) is confirmed to resolve normally, confirming the disputed outcome above is specifically about the tie.

**A finding surfaced while building Case 2, not assumed from reading `belief-query.ts`'s prose:** `recordFact`'s own eager-resolution loop filters `eligibleOlder` candidates by a STRICT `believedAt` inequality, so two same-tick writes never contend with each other at write time at all — both land live, untouched, and the tie is caught only later, lazily, the first time something queries. This is recorded in Case 2's own header as "found, not assumed," and is itself a small illustration of why the tie case matters: a store that only resolved contradictions eagerly would let this exact race slip through silently until a query happened to notice.

## Decision 3 — three corrections to a prior claim, found by checking rather than inheriting

**Finding 1 (Case 10, and the reason its own regex is narrower than its first draft): a switch/case leg produced a real false positive against `lib/store/belief-query.ts`'s `switch (check.outcome) { ...; case "disputed": ... }`.** The task brief's own suggestion to pin "Memory.status is never read by any engine" was answered as an HONEST PARTIAL PIN — but the first draft of the textual scan also matched bare `case "believed":`/`case "disputed":` lines wherever they appeared, on the theory that a switch branching on either literal was equally suspicious no matter what it switched on. Run against the real tree, this flagged a `switch` over `ContradictionCheck.outcome` (a completely different type, which happens to share the string `"disputed"` with `Memory.status`) as an offender. Rather than special-case that one known false positive — which would only hide the next unrelated switch reusing either literal — the switch/case leg was removed entirely, and the case's own header records the false positive as the reason, with a regression test (`Case 10`'s own third `it`) proving the narrower regex correctly does NOT flag it. What remains, checked directly, still finds zero offenders for a direct `.status === "believed"|"disputed"` comparison.

**Finding 2 (Case 6): a chosen corpus pair shared no vocabulary at all, producing a cosine score of exactly zero instead of the intended "ranks a stale, forgotten statement as a real match" demonstration.** `rankBySimilarity("what's my coffee order?", [{text: "I usually get an oat milk latte."}])` scores `0` — a real, correct answer from the baseline (nothing shared), but not what that sub-test was built to show. The statement text was corrected to `"My usual coffee order is an oat milk latte."`, which shares "coffee"/"order" with the query and produces a genuine nonzero score, making the intended point (the baseline ranks even a long-forgotten statement as a real, positive match — no notion of staleness exists in the function at all) actually true of the assertion, not merely of the prose around it. Caught by running the suite, not by re-reading the test.

**Finding 3 (the deleted Case 11, and the largest correction in this milestone): the task brief's own premise — "a behavioural agreement guard now exists in `domains/**`" — was FALSE against the branch this milestone was cut from, and became TRUE only once `main` was merged mid-build.** `m7-failures` was cut from `dd477d5` (M6's own merge commit). A `git grep -rn "TIER_RANK|resolveTierSplit|newerSourceOutranks"` across that commit's own `domains/personal-assistant/__tests__/**` found nothing — no such guard existed there. A file matching the brief's description was independently drafted (`case-11-tier-rank-tables-behavioral-agreement.test.ts`), built entirely on PUBLIC APIs (since `lib/contradiction`/`domains` were frozen and `newerSourceOutranks` was not, at that commit, exported). Before finalizing the report, `git diff main -- lib domains` was run as this milestone's own required pre-push check and came back NON-empty: `main` had advanced, in the meantime, past the commit this branch was cut from, to `c8dc497` — the mark-M6-done PR (`.genesis/PLAN.md`'s own house convention), which both exports `newerSourceOutranks` from `domains/personal-assistant/store.ts` FOR EXACTLY THIS PURPOSE and adds `domains/personal-assistant/__tests__/tier-rank-agreement.test.ts`, an exhaustive 2×2 behavioural-agreement check between the two tables — the task brief's premise, true after all, just not yet landed on this branch's own base. `main` was merged into `m7-failures` (a clean fast-forward, `git diff main -- lib domains` empty afterward), and the independently-drafted Case 11 was deleted rather than kept alongside a now-duplicate, less-exhaustive check — keeping both would have meant two guards for the same fact, one strictly weaker than the other, which is its own small version of the "speculative flexibility" this account's own house rules warn against. The now-merged guard's own header discloses precisely what it cannot catch: "both modules agreeing on a ranking that is jointly wrong." **CORRECTION (post-approval, verifier-caught, not self-found): this ADR originally credited Case 8 with closing that gap. That claim was checked and is false.** Case 8's two sub-tests both construct `older` and `newer` with `humanAvowal` — same tier (`"direct-avowal"`) on both sides, in every sub-test. `resolveTierSplit`'s own same-tier branch (`tier-split.ts`) is a literal hardcoded check (`newerTier === "direct-avowal" ? "superseded" : "disputed"`) that never reads `TIER_RANK` at all — so Case 8 exercises zero cross-tier comparisons and provides zero coverage of the numeric ordering a joint flip would corrupt. Stated plainly instead of re-credited: **Case 8 pins exactly what it pins** — that recorded `Memory.confidence` plays no role in the same-tier `superseded` outcome (0.9/0.1, both directions). **The `lib`-side cross-tier ordering is pinned elsewhere, already, and predates this milestone**: `lib/contradiction/__tests__/contradict.test.ts`'s own "§5.1's split, the other two cases — cross-tier disagreements" block asserts literal `superseded`/`disputed` outcomes for BOTH cross-tier directions (`derived-inference` older vs. `direct-avowal` newer, and the reverse) — a frozen, pre-existing guard this milestone had no need to add to. **What is genuinely NOT pinned, named precisely rather than glossed over**: no test in this suite, in `lib/contradiction/__tests__`, or in the merged `domains/personal-assistant/__tests__/tier-rank-agreement.test.ts` catches the two tables agreeing on a JOINTLY WRONG cross-tier ordering (both flipped identically) — the merged guard's own disclosed limit, still open. That is the coordinator's own finding, being fixed separately in `domains/**`, outside this milestone's freeze boundary.

## Decision 4 — regression pins for already-learned behaviour: full pins, deliberately re-tested one layer up from where each was first proven

Cases 3, 4, 5, 7, 8, and 9 each restate a fact this project already proved once, at the layer it was first built (`lib/decay/__tests__`, `lib/contradiction/__tests__`, `lib/contracts/__tests__`, `domains/personal-assistant/__tests__`) — deliberately, per this milestone's own brief ("Pin the numbers so a future corpus edit that quietly makes the contrast vanish fails loudly," restated by the brief for several of these facts specifically). Each is built through the REAL production call path (`recordFact`/`query`, not a synthetic fixture standing in for it) wherever that path exists, so a regression anywhere between the original proof and the shipped behaviour — not only in the original function itself — is caught here:

- **Case 3** — source revocation tombstones a memory at its freshest, highest-confidence, most-favourable moment (elapsed time zero, `never-decays`, confidence 0.95), and a non-revocable source's memory is confirmed, by the same call, to be correctly left alone (the discriminating half of the claim, not just the positive half).
- **Case 4** — the exact §8 contrast (0.53033.../0.31623..., matching `baseline.test.ts`'s own hand-worked arithmetic to 10 decimal places), robust across five phrasings independently probed against the real `rankBySimilarity` before being hardcoded (not copied from `baseline.test.ts`'s own five, nor from the mark-M6-done commit's own five — a third independent set, all confirming the same qualitative result), plus a structural sub-test that the real engine's own `query()` signature has no free-text parameter for wording to sway at all.
- **Case 5** — the compile-time tombstone refusal, re-proven one layer up from `lib/contracts`/`lib/store`'s own proofs, against `StoreState.live` — the field every real caller in this codebase actually reads and writes, which did not exist until M6.
- **Case 7** — `forgetFloor >= 1`, both at the exact boundary and past it, both at `decay()`'s own layer and end-to-end through a real query at elapsed time zero; a sanity case confirms the boundary is exactly `>= 1`, not an overtightened rejection of merely-high floors.
- **Case 8** — 0.9-vs-0.1 confidence, both directions, both through `contradict()` and through the real write path, with the winning memory's own low confidence reported honestly rather than inflated.
- **Case 9** — immutability re-proven against a real, domain-constructed memory (a genuinely different assignability check than `lib/contracts`' own fixture-based proof, now that a real `PredicateValueMap`-derived `TValue` flows through), plus the recorded-vs-computed split shown end to end via real revocation.

## Decision 5 — Case 6: all four `BeliefAnswer` variants, reconstructed as an actual vitest-reported test, not only a script

`scripts/demo-memory.ts` already reaches all four variants via `node:assert`, but that script is not part of `npm test` and its failures are not reported the way a vitest failure is. Case 6 rebuilds the same claim with a trimmed, three-predicate corpus, and adds the other half of §2's own argument as a direct contrast: `rankBySimilarity`, run against corpora shaped like the disputed/doubted/unknown cases the engine just reached, never refuses and never represents disagreement — it returns a ranked, scored list every time, including for a corpus whose only entry the real engine would have long since tombstoned.

## Decision 6 — post-approval verifier findings, addressed here rather than left standing

This milestone was approved, then independently falsified against (reversal, boundary probes, directive removal, source injection) by a verifier who found three things. Two were this milestone's own to fix; both are recorded above at the point they actually belong (Decision 3's Finding 3, for the Case 8/tier-rank-agreement overclaim; Case 10's own file header and tests, for the destructuring gap) rather than only here, so a reader checking either case's own reasoning sees the correction in place, not merely referenced from an ADR they might not open. This section is the pointer and the closing note for both, plus the one purely informational item.

**The Case 8 overclaim (Decision 3, Finding 3) is corrected above, in place.** Summary for this section only: this ADR originally said Case 8 "is exactly the test that would catch" the merged `tier-rank-agreement.test.ts`'s own disclosed gap (both tables agreeing on a jointly-wrong cross-tier order). Checked and found false — Case 8 is same-tier-only on both sub-tests, and `resolveTierSplit`'s same-tier branch never reads `TIER_RANK`, so Case 8 provides no cross-tier coverage at all. The correct citation for the `lib`-side cross-tier ordering is the pre-existing, frozen `lib/contradiction/__tests__/contradict.test.ts`; the jointly-wrong-ordering gap itself remains open and is being closed separately, in `domains/**`, outside this milestone's freeze boundary — not rebuilt here as a weaker duplicate of a fix already assigned elsewhere.

**The Case 10 destructuring gap is corrected above, in place, and closed rather than merely disclosed.** Summary for this section only: Case 10's own disclosed-limits list named reflection, a renamed re-export, and a dynamically assembled string, but omitted the single most ordinary way to read a field in TypeScript — destructuring (`const { status } = candidates[0]; if (status === "believed")`). Independent verification injected exactly that shape into a real engine file in a scanned root and every sub-test still passed. The fix was cheap and did not reintroduce the earlier `switch`/`case` false positive (a different axis — that one was about what a `case` label's STRING happened to match regardless of the switched-on expression; this one is about the LEFT-HAND SIDE of a direct comparison): the pattern now matches `status` as a bare word-boundary token, not only when preceded by a literal `.`, so a destructured local is caught the same way a property access already was. Checked against every real non-comparison use of the word `status` already in the scanned roots (object-literal construction, a renaming destructure that discards the value) to confirm the broadened pattern does not newly misfire on legitimate code — it does not; the scan still finds zero real offenders. What remains genuinely undisclosed-turned-disclosed, stated at full strength rather than softened: a comparison against a variable holding the string `"believed"` (as opposed to the literal itself) is a further, real, still-open gap this narrower fix does not close either, named here rather than assumed away now that the obvious one has been.

**Finding 3, informational — Case 1's own M8 forward note, checked against the real, now-merged M8 code, not left as an open question.** Case 1's header and this ADR's own Consequences section (below) name a UI holding a stale `StoreState` across an async gap as the shape most likely to reintroduce the interleaved-affirm race Case 1a demonstrates. `components/DemoAssistant.tsx`, `components/AnswerPanel.tsx`, `components/BaselinePanel.tsx`, and `app/page.tsx` (M8, merged in `e679ea7`) were checked directly, not assumed clean: `grep -n "useEffect\|useCallback\|setTimeout\|async \|await "` across all four returns zero matches. There is no async gap anywhere in M8's own component tree for a stale snapshot to survive across — event handlers are recreated every render and read the freshest `StoreState` synchronously, the same monotonic-threading discipline `scripts/demo-memory.ts` already established. The risk flagged forward did not land in M8. This does not retroactively make Case 1 a full pin — the type-level gap it names is still real, and a future async UI change (a debounced input, a fetch-backed integration) could still reopen it — but the specific instance this milestone's own forward note worried about was checked, not merely hoped past.

## Consequences

- Positive: both required §10 races are pinned, honestly labelled — one full, one partial, with the partial label defended by naming exactly what a single-threaded, synchronous runtime makes unconstructable, not merely asserted out of caution.
- Positive: the required shared-deliverable baseline contrast (`PLAN.md`'s M7 criterion 4) passes as a real test against the unmodified baseline and the exact §8 corpus, with the underlying scoring assertion confirmed exactly as the plan predicted — no finding of the kind §8's own text warned to watch for ("if this assertion cannot be made to pass... that is a finding to report").
- Positive: three real corrections were made while building this suite, self-found by running the suite rather than only reading it (a false-positive regex leg removed and regression-tested; a zero-overlap test fixture corrected; a redundant, weaker duplicate of a since-merged guard deleted in favour of citing the stronger one) — each recorded in the case file and this ADR, not silently fixed.
- Positive: two further, real corrections were made post-approval, by an independent verifier who falsified this milestone's own claims (reversal, boundary probes, directive removal, source injection) rather than reading them — an overclaimed citation of what Case 8 covers (Decision 3, Finding 3), and an under-disclosed blind spot in Case 10's own absence claim (destructuring, Decision 6). Both are corrected in place, not only noted here. Every one of this milestone's eight FULL-PIN labels survived that falsification; no partial label was found to be under-claiming.
- Negative / cost, disclosed: Case 1's own partial pin means the interleaved-affirm race is demonstrated and shown-avoided-by-convention, not closed by any type-level guarantee. A future stateful caller that holds a `StoreState` across an async gap could reintroduce Case 1a's exact shape, and nothing under `lib/store/**` or `domains/personal-assistant/**` would stop it. This is this milestone's own weakest case, named as such in the report, not the strongest one presented as if it were the average. Checked directly against the now-merged M8 (Decision 6): no such async gap exists in its own component tree, so the specific risk flagged forward did not land — but the underlying gap this milestone can pin is still open for whatever comes after M8.
- Negative / cost, disclosed: Case 10's textual scan still cannot see through reflection, a renamed re-export, a dynamically assembled property access, or a comparison against a variable holding the target string rather than the literal itself. Destructuring — the gap a verifier found and this milestone under-disclosed at first approval — is now closed, not merely listed; the remaining gaps are stated at the same full strength, not left implicit in a shorter list that reads as more complete than it is.

## Alternatives rejected (summary, cross-referenced above)

- A true, thread/async-based interleaving test for Case 1 — rejected because none is constructible in this codebase's fully synchronous call graph; building one would have required adding concurrency machinery to `lib/store/**`, which is frozen and out of this milestone's scope.
- Keeping the switch/case leg in Case 10's regex after finding its false positive, special-cased around the one known offender — rejected because it would only hide the next unrelated switch reusing either literal, not close the actual gap.
- Keeping the independently-drafted Case 11 alongside the since-merged `domains/personal-assistant/__tests__/tier-rank-agreement.test.ts` — rejected as a strictly weaker duplicate once the stronger, exhaustive, already-merged guard was available. (Its own disclosed gap — both tables agreeing on a jointly-wrong cross-tier order — was first mis-credited to Case 8 in this ADR, then corrected once the verifier checked the claim; see Decision 3, Finding 3, and Decision 6 below. The gap remains genuinely open and is being closed separately, in `domains/**`.)
- An AST-based (rather than textual/regex) absence scan for Case 10, matching `lib/store/__tests__/architecture.test.ts`'s own later rewrite — considered, and not built, for a single narrow absence claim; the textual scan's own disclosed limits are stated plainly instead of closed at that cost.
